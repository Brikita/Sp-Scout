# SpareScout audit and fixes — 14 September 2026

## Fixed in this checkout

- Approval review now uses the server-returned request and locks editing until the buyer chooses Edit request.
- Missing prices stay missing; rejected or failed results cannot become the best offer. Stock must be confirmed before selection. Condition is preserved and invented confidence scores are removed.
- Provider recipients are matched by phone instead of array order.
- Live execution enforces machine-readable calling-window boundaries before contacting CALL-E.
- Live availability requires D1 storage and a sufficiently long approval secret.
- Continue no longer submits the final wizard step; starting another search resets the wizard.
- Fixed a decorative element escaping the mobile results panel and causing horizontal page scrolling. Comparison tables scroll inside their own container.
- Interrupted monitoring of a known active call stays in the monitoring state with a History link.
- Corrected SDK, D1 and Web Crypto types; excluded unrelated work checkouts; added type checking to the normal check command.
- Patched React/RSC, Vite, vinext, Cloudflare tooling and the nested migration-tool esbuild dependency. npm reported zero vulnerabilities after installation.

## Validation

- Type checking, Cloudflare build, rendered routes, contract tests and lint passed after the runtime updates.
- Four rendered/API tests and 24 contract tests cover the current automated suite. The API test checks approval rejection, token tampering and deterministic fixture retries.
- Vercel production build passed.
- Browser checks passed for the three-step mobile fixture flow, approval, results and contained comparison-table scrolling at 390 px. Local OCR correctly read a synthetic printed reference and transferred it only after confirmation.
- Public demo returned HTTP 200 but still shows the older UI.

## Remaining limitations

- No published consenting-supplier pilot has been verified. Mocked SDK tests do not establish audio quality or real sourcing performance.
- A process failure after provider acceptance but before saving/returning the call ID still requires durable reconciliation. Same-token retries use provider idempotency while approval remains valid. No terminal webhook receiver or background reconciliation worker is implemented.
- Public Vercel fixtures have no D1-backed history or live calling; downloadable briefs work without D1.
- OCR reads printed text and downloads language assets. It does not identify an unlabelled part or prove fitment.
- Supplier discovery opens Google Maps search; it does not import a verified contact directory or establish consent.
- Local changes have not yet been released. The required public video and final Devpost submission remain unverified.

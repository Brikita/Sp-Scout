# Live-call demo plan

Use this plan only if one or two people in a currently supported CALL-E recipient/language combination have explicitly agreed to receive the demo call. Kenya/English is currently rejected before call creation. The safest convincing setup is a teammate or friendly parts professional role-playing a supplier with a prepared inventory card. Do not surprise-call businesses during the recording.

## Prepare before recording

- Confirm the exact GitHub commit is deployed to the private D1-backed Site and verify live mode before recording.
- Configure the trusted live environment with CALL-E, D1, the approval secret, and an authorized call window that covers the recording.
- Confirm each recipient's number, region, language, provider coverage, consent, availability, and role-play inventory facts.
- Use a real vehicle request and a printed part reference. Avoid personal VINs or customer data in the public video.
- Run one private rehearsal. Confirm audio, result extraction, status polling, and history recovery.
- Keep the Safe demo available as a fallback. Never present fixture output as a real call.

## Supplier role-play card

Give each consenting recipient a short card, not a script. Example:

- Part: front-left wheel bearing
- Fitment reference: 43550-12030
- Vehicle: 2014 Toyota Corolla
- Brand and condition: SKF, new
- Price: USD 145
- Quantity: 3
- Delivery: same day to Chicago, IL
- Evidence phrase: “I checked reference 43550-12030 in our catalogue.”
- Boundary: if asked to reserve or purchase, say that a separate confirmation is required.

## Recording sequence — target 2:30

**0:00–0:20 — Problem.** Show the home page and say: “Parts inventory often lives behind phone calls. Buyers repeat the same fitment details and still struggle to compare the answers.”

**0:20–0:55 — Request.** Enter the vehicle and part, demonstrate the label reader briefly, confirm the extracted reference, then set the budget and delivery location.

**0:55–1:15 — Safety.** Select the consenting live contact. Show the consent and call-window controls. Pause on the generated plan and say: “The browser cannot alter the approved recipients or task. No payment, purchase, or reservation is authorized.”

**1:15–1:40 — CALL-E.** Approve once. Show the in-progress state while the pre-arranged recipient answers. Use a screen recording or a second camera to capture a few seconds of the consenting recipient's phone ringing; do not expose the full number.

**1:40–2:15 — Evidence and decision.** Show the completed result, fitment evidence, stock, condition, price, delivery, readiness filter, and comparison view. Point out any incomplete answer rather than hiding it.

**2:15–2:30 — Close.** Show the downloadable brief and project page. Say: “CALL-E turns phone-only inventory into comparable evidence, while the buyer keeps control of every consequential step.”

## If the live call does not complete cleanly

Keep recording. A no-answer or incomplete field demonstrates honest failure handling if the interface labels it accurately. Then show the separately labeled fixture path for the full comparison experience. Do not splice fixture results into the live sequence without labeling them.

## Evidence to retain

- Recording date and the deployed commit SHA.
- Consent note for each participant, kept private.
- CALL-E run ID and masked call history.
- Final public video URL and the exact judge-facing demo URL.
